# 1.2.0 版本说明

## ✨ 新增功能

### 统一链接管理与二维码分享
- 共享链接与访客上传链接合并为**统一入口**：单一 `config/links.json`（`kind` 字段区分 `share` / `upload`），提供 `/api/links`、`/api/delete-link` 统一读写接口；旧的 `shares.json` / `upload_links.json` 首次访问时自动一次性迁移
- 管理页新增「🔗 链接管理」：同时显示共享链接与访客上传链接，支持一键复制、删除、创建
- **二维码分享**：每个链接卡片新增「📷 二维码」按钮，扫码即可在手机端直接打开对应链接（`/api/qr/{id}` 生成 PNG，链接地址为公网可访问的完整 URL）

### 文件夹树状显示
- 管理页文件管理改为**可折叠文件夹树**：嵌套缩进、层级竖线、文件夹属性标签（文件数 / 总大小）、逐层操作按钮；**默认收起，点击展开**
- 后端新增 `/api/files/tree`（`utils/filetree.build_file_tree`）：递归构树 + 文件夹权限过滤 + 全层级文件扁平化（`flatten_files`）
- 分享页（普通文件夹模式）同步改为树状展示（`build_file_tree` + `collapsed` 折叠驱动）
- 管理页搜索自动展开命中路径，深层结果可见

### 相册分享页（树形 → 筛选栏结构）
- 相册模式主界面不显示目录树，全层级图片 / 视频**分区分栏展示**（🖼 图片区 / 🎬 视频区，各自网格 + 分区标题 + 计数徽章）
- 新增**筛选栏**（sticky 吸顶）：
  - 类型胶囊组（全部 / 图片 / 视频，纯文字、无数字，选中为白色胶囊——与整体风格统一）
  - 筛选信息行（动态摘要，如「🖼 图片 · 📁 1234 · 3 张」）
  - 目录筛选下拉（列出全部子目录，选某目录 = 该目录及其子目录的媒体，与类型筛选可组合；结果为空显示网格内空态）
- 灯箱图片前后切换集合 = 当前筛选（类型 + 目录）下可见的图片，不会"穿越"到被筛掉的媒体
- 横幅封面改为 **3~4 张交叉淡入轮播**（无图时 📷 占位，不再破图）

### 视频播放页（选集 + 连播）
- 全新播放页 `share_video.html`（浅色统一风格，与相册页一致）：
  - **选集面板**：全层级视频列表（首帧缩略图 + 编号 + 文件名 + 大小），点击切源不重开窗口，当前集高亮 + "▶ 播放中"角标
  - **自动连播**开关（默认开启，播完自动下一集）、上一集 / 下一集
  - 视频下方**胶囊菜单栏（居中）**：返回共享 / 上一集 / 下一集 / 连播 / 下载 / 全屏，圆形图标按钮，移动端自动收窄为纯图标
  - 「全屏」为**页面内占满模式**（视频尽量铺满、不进入 OS 全屏，保留浏览器界面）
  - 键盘快捷键：`←`/`→` 切集、`F` 全屏、`A` 连播、`D` 下载
- 相册 / 文件夹页点击视频**同标签页**跳转播放页（不再开新窗口），浏览器返回键可回到共享页
- **返回共享免密码**：播放页"返回共享"携带短期 access 令牌跳回共享页，共享页识别 `?access=` 后直接渲染内容（令牌失效时回退到密码卡），无需重新输入密码
- 页面标题显示在浏览器标签页（含集数前缀），去除顶栏，视频空间尽量大

### 同片源多格式转码工具（transcode.py）
- 独立标准库脚本（无 pip 依赖，仅依赖系统 ffmpeg）：一个源视频生成多个网页可播版本
  - **四种视频格式可选**（`--formats h264,hevc,av1,vp9`）：H.264 / HEVC 出 MP4（AAC + faststart + hvc1），AV1 / VP9 出 WebM（Opus）；多选时文件名带格式后缀（`xxx_hevc.mp4` / `xxx_av1.webm` …），单选保持原名
  - **GPU 优先 + 自动回退**：每个格式各持一条编码器回退链（NVENC > QSV > AMF → CPU），首选失败（如 NVENC 对个别源报 `-22 Invalid argument`）自动沿链重试，成功时打印实际编码器，整链失败才记失败；`--no-gpu` 强制全 CPU
  - **统一质量入口**：`--quality low/medium/high` 按各编码器质量曲线映射推荐 CRF/CQ（修正"AV1 反比 H.264 大"的曲线差异）；`--crf` / `--gpu-cq` 可显式覆盖
  - **分辨率封顶**：`--max-height`（默认 1080，0 关闭）等比只缩不放、偶数对齐，网页场景无需 1440p/4K 像素
  - **音频分格式码率**：`--aac-bitrate`（默认 96k）/ `--opus-bitrate`（默认 64k），比统一 128k 更省
  - 幂等（产物比源新则跳过，`--force` 重转）、冲突安全（目标撞源先挪 `.orig`）、失败安全（删不完整产物、保留源）、`--delete-source` 批处理删源
- 相册页 / 视频播放页据此按"片源"聚合：同片源多格式分片并成一张卡片 / 一条选集

### 视频播放页多格式分片选择
- 同一"片源"（如 `xxx_h264.mp4` / `xxx_hevc.mp4` / `xxx_av1.webm` / `xxx_vp9.webm`）自动并成**一条选集**，胶囊菜单栏内**格式下拉框**（自动 + 各实际具备的格式）
  - **自动** = 挂全部 `<source>`，浏览器按可播优先级（h264 → hevc → vp9 → av1）自选第一个能解的分片；指定某格式 = 只挂该格式分片强制走该编码
  - `?fmt=` 深链保持选择；切到没有该格式的下一集自动回落"自动"；下载跟随所选分片
- 相册页 `dedupeVideoFiles` 按"去扩展名 + 去格式后缀"分片源键分组，四个分片仍只显示一张卡片（与播放页片源键一致）

### 访问数据看板（独立页）
- 设置页「📊 访问数据看板」按钮（置于"保存设置"旁）→ 独立页 `/dashboard`，数据接口 `/api/share-stats` 受 token 保护
  - 4 张 KPI 指标卡（总 PV / UV / 活跃链接 / 今日访问）+ 近 7 天 CSS 柱状图（峰值高亮 + 数值标签）+ TOP 10 IP + 各链接 PV（按 PV 降序）；未授权态、加载态、响应式齐全
  - 数据 = 磁盘已落盘日志 + 内存未落盘缓冲（写批量、读实时）

### 目录结构重组 + 热写
- 数据目录按职责三分：`config/`（人手工改：config.json / folder_permissions.json）+ `data/`（业务数据：users / secret / links / access_log，备份必保）+ `cache/`（可再生产：thumbs / zips）；首次启动一次性幂等迁移，旧 `.thumbs/` 自动清理
- 热写优化（`utils/hotstore.py`）：view_count 与访问日志不再逐请求 fsync 写盘，改为**进程内存聚合 + 后台线程定期原子落盘**（间隔可配 `hot_flush_sec`，默认 30s），请求路径微秒级；进程退出 atexit 兜底

### 配置化（新增 11 项设置）
- 设置页两张新卡片，全部落到 `config.json`，保存即生效（多数按请求动态读取；限流 / 热写间隔保存时热生效）：
  - 「上传与共享」：上传单文件上限 `upload_max_mb`（0=不限）、允许扩展名 `upload_extensions`（`*`=全放行）、默认共享有效期 `default_share_days`、默认共享模式 `default_share_mode`
  - 「安全与性能」：登录失败锁定阈值 `login_max_failures`、冷却时长 `login_cooldown_sec`、管理会话有效期 `token_ttl_hours`、访问日志保留条数 `access_log_max`、热写落盘间隔 `hot_flush_sec`、缩略图尺寸 `thumb_size_list` / `thumb_size_preview`
- 旧 `config.json` 缺键时自动补齐默认值（幂等、不覆盖已改过的值）

### 三页风格统一 + 二维码真实预览
- 链接管理 / 用户管理 / 系统设置三页统一视觉体系（`page-head` 图标页头 + `setting-card` 卡片 + 图标标题）；用户管理权限改九宫格、表格样式与看板对齐；卡片间留间隔，深色模式全适配

## 🔒 安全加固

| 项 | 说明 |
|---|---|
| 路径穿越防护 | `utils/security.safe_join` 守卫全部文件接口（下载 / 删除 / 上传 / 改名 / 建目录 / 共享内容 / 视频流 / 缩略图 / zip）；上传文件名做 basename 净化 |
| 登录限流 | 按 IP 计数，连续 5 次失败冷却 300s |
| 管理 API 鉴权 | HMAC-SHA256 签名 token（`Authorization: Bearer` 或 query 透传），保护用户 / 文件 / 链接 / 设置类接口；公开分享、上传、媒体接口保持开放 |
| 密码哈希升级 | SHA-256 → **bcrypt**，存量用户下次登录透明升级（`verify_password` 双格式兼容） |
| 共享密码 + 过期补全 | 共享内容 / 单文件下载 / 文件夹下载 / 视频流全部补齐密码闸门与过期校验；密码验证后签发**短期 access 令牌**，后续请求免重复验证 |
| 上传限制 | 单文件 100MB 上限 + 扩展名白名单（均可配置），超限 / 非白名单即时 400/413 并清理残留 |
| HMAC 密钥随机化 | 会话 token 密钥不再写死：优先 `XS_TOKEN_SECRET` 环境变量，否则首次启动随机生成 32 字节持久化到 `data/secret.key`（仅存部署机、不入库） |
| 过期链接清理 | 启动时扫描并删除过期链接记录（`load_expired_links` / `delete_links`），不留僵尸数据 |
| 访问日志滚动上限 | 日志按 `access_log_max`（默认 5000，可配 0=不限）滚动裁剪，防 JSON 无界增长 |
| zip 生命周期 | 不再按 24h 时间过期：文件夹内容变更（指纹比对）即删旧 zip 重新打包；`cache_max_gb`（默认 10G，可配）超量时按最旧优先裁剪 |
| 依赖锁定 | `requirements.txt` 全部依赖 pin 到已验证版本（含 `qrcode`、`bcrypt`），避免日后拉到破坏兼容的新版；注释标注 PyAV 需系统 ffmpeg |

## ⚡ 性能（视频 P0）

- 视频流端点改**同步 def**（线程池执行，慢客户端不阻塞事件循环）+ **4MB 大分块**
- `Content-Type` 按扩展名推断（不再写死 `video/mp4`，webm/mov 等正常解码）
- **ETag + Cache-Control**：公开流 `s-maxage=3600`（Cloudflare 边缘可缓存，二次 / 拖动走边缘 206）；密码流 `no-store`（共享过期后缓存立即失效）
- 缩略图 / 预览图 `Cache-Control: public, max-age=30d`
- 配合 Cloudflare 的缓存规则建议：`contains(uri.query, "access=")` 一律 Bypass；`/api/video-stream/`、`/api/share*-download/` Cache eligible + Respect Origin

## 🧱 工程结构

- `main.py` 精简为 ~58 行入口，按功能场景拆分：
  - `routers/`：`auth` / `users` / `files` / `shares` / `share_media` / `share_log` / `media` / `settings` / `upload_links` / `zip_tasks`
  - `utils/`：`storage`（JSON 原子读写 + links 统一存储 + 目录重组迁移 + 默认配置补键）/ `ziptask`（统一 zip 打包 + 变更删旧重打包 + 容量裁剪）/ `filetree`（树构建）/ `security`（safe_join / 限流 / token / 哈希 / 上传限制）/ `share`（共享查找 / 解锁闸门 / 视频 MIME）/ `hotstore`（view_count 与日志内存聚合 + 定期落盘）
- 前端新增 `common.js`（XSLib：转义 / 格式化 / 请求封装 / 轮询 / token 管理 / 会话恢复），各页面事件委托化，全量 HTML 转义防 XSS
- 修复：视频流 `unquote` 未导入 NameError、zip 任务未知 ID KeyError、share-content 文件大小缺前缀 FileNotFoundError、分享页 bootstrap bundle 缺失 Popper
