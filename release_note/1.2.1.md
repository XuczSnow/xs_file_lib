# 1.2.1 版本说明

> 相对 1.2.0 的增量：视频分片（fMP4/DASH）+ faststart 诊断 + 缩略图 WebP + 资源访问地址可配 + 二维码美化与预览修复 + 离线脚本归置到 `tools/`。

## 🎬 视频分片 / 边下边播（路线 B：fMP4 + DASH）

- **分片切片**：`tools/make_dash.py` 离线把网页视频切成 fMP4 单文件 DASH（`manifest.mpd` + `manifest-streamN.mp4`）。视频 `-c copy` 零重编、秒级；音频若源非 AAC（如 WebM 的 Opus）自动转 AAC；fMP4 容器对 H.264 / HEVC / AV1-in-fMP4 通吃。
- **服务端生命周期**：`utils/dashtask.py` 惰性切片（首次请求才切）+ 源指纹（mtime+size）失效即重切 + 纳入 `cache_max_gb` 容量裁剪（最旧优先）；子目录 key 用「UPLOAD_DIR 相对路径 + 正斜杠归一化」算 md5，离线预生成与在线惰性命中同一目录。
- **两个端点**（`routers/share_media.py`，复用现有鉴权 / 过期 / 路径穿越守卫）：
  - `GET /api/video-dash/{id}/{file}`：返回 `application/dash+xml` manifest，MPD 的 `BaseURL` 改写为分片端点前缀（含 `access` 令牌）
  - `GET /api/video-dash-media/{id}/{file}/{seg}`：分片单文件，4MB 分块 + Range/206 + ETag（**中文文件名走 md5 摘要**，HTTP 头安全）；公开流边缘缓存 1h、密码流 `no-store`
- **前端探测回退**（`share_video.js` + `static/vendor/dash.js`）：dash.js 已部署**且**该分片已切 fMP4 时走分片播放（秒起播 / 拖动只拉小片 / Cloudflare 边缘命中更细）；dash.js 探测失败、该分片未切片（manifest 404）、或 manifest 加载失败/超时 → **自动回退原生 `<source>` 渐进式**，零风险。
- **修复 v5.3 `reset()` 异常中断整个播放页的 bug**：dash.js v5 中 `player.reset()` 在 `initialize()` 之前调用会抛异常，旧代码在 try 外裸调 → 首次进页即中断、连渐进式回退都执行不到（视频彻底不能播）。修复：`dashInited` 标记守护（仅已初始化的 player 才 reset）+ 全程 try/catch + 回退时 `destroy()` 彻底清场 + 监听 dash.js player 的 `ERROR` 事件（manifest 404 等内部错误）双重兜底回退。
- **全局 CORS 放行（"资源访问地址"跨源播放修复）**：当设置里的资源访问地址（mediaBase，如 localhost/外网/隧道）与页面源不一致时（典型：页面从 127.0.0.1 打开、资源地址配成 localhost），dash.js 用 XHR 拉 manifest/分片属跨域请求，`Range` 头还会触发 OPTIONS 预检 → 浏览器整段 block（表现为"始终渐进式 + 控制台 CORS 报错"；渐进式 `<video>` 不受 CORS 约束所以不受影响）。`main.py` 注册全局 `CORSMiddleware`（`allow_origins="*"` + 暴露 `Content-Range/Content-Length/Content-Type/ETag` + 自动应答预检）；共享媒体靠 share_id/access 令牌鉴权、令牌在 query 不用 cookie，放行 `*` 无安全风险。实测跨源 GET 200 + Range 206 + OPTIONS 预检 200 全绿。
- 依赖系统 ffmpeg（`config.json` 的 `ffmpeg_path` 可配，留空取 PATH）；无 ffmpeg 时 manifest 404，前端静默回退渐进式。

## ⚡ faststart（moov 前置）诊断工具

- `tools/faststart_check.py`：扫描 `.mp4/.m4v`，解析 top-level box 判 **moov 位置 + 体积**（moov 在尾部的文件起播要先拉数 MB 元数据，故卡）
- 默认 dry-run 只出报告；`--fix` 用 `ffmpeg -c copy -movflags +faststart` **无重编码**重排到独立目录（`cache/faststart`），**绝不改写 uploads 源文件**；`manifest.json` 记源指纹，幂等 + 源变更即重排
- 小 moov（≤ `--min-moov`，默认 1MB）标记 skip，避免白做

## 🖼 缩略图改 WebP

- `routers/media.py`：图片 / 视频首帧缩略图由 JPEG 改 **WebP**（比 JPEG 小 30~50%、保留透明通道）；缓存文件 `.webp`、响应 `Content-Type: image/webp`；`<img>` 直接引用端点自动获得 webp（前端无需改）

## 🌐 资源访问地址可配（IPv4 / IPv6）

- 设置页文案「IPv6 访问地址」改为**「资源访问地址」**（弱化 IPv6、支持 IPv4），探测超时可配

## 🎞 DASH 播放"有声无画"修复：补全 HEVC 的 MPD codec 串

- **根因**：ffmpeg 的 DASH muxer 对 HEVC 只在 MPD 里写**裸** `codecs="hvc1"`（不带 profile/level）。浏览器 `MediaSource.isTypeSupported('video/mp4; codecs="hvc1"')` 对裸串返回 **false**（只对 `hvc1.1.6.L93.B0` 这类带 profile/level 的完整串认账），于是 dash.js 按 MPD 的 codecs 做能力 gate 时**视频 Representation 被丢弃、只留音频轨** → 表现为"有声无画"（且因音频成功判定为"部分成功"，不触发整段回退渐进式）。H.264 / AV1 的 MPD 串本身完整（`avc1.xxxx`/`av01.xxxx`），不受影响。
- **修法（serve 侧兜底 + 生成侧写全）**：
  - `routers/share_media.py`：`_complete_mpd_video_codecs` 在改写 `<BaseURL>` 的同一处把裸 `hvc1`/`hev1` 补全为带 profile/level 的完整串——meta 有 `video_codecs`（生成时 ffprobe 探测的精确串）用之；存量缓存 meta 无该键时从 MPD 的 `width/height` 推保守 level（L93≈1440p / L123≈4K / L183≈8K）兜底。**对已生成的缓存即时生效，无需重切**
  - `utils/dashtask.py` + `tools/make_dash.py`：切片时 ffprobe 读源 HEVC 的 `codec_name/profile/分辨率`，写完整串进 meta `video_codecs`（Main→`hvc1.1.6`、Main10→`hvc1.2.4`）
- 新增回归用例（`tests/test_regress.py`）：单元（meta 有串 / 存量推 level / 8K 推 L183 / 非 HEVC 串不动）+ 端到端（manifest 端点对存量 HEVC 缓存输出补全后 MPD、无裸 `hvc1` 残留）
