# 1.2.2 版本说明

> 相对 1.2.1 的增量：设置页"系统更新"卡片（在线检查/拉取/回滚）+ 一键安装/卸载脚本（`install.py` + `serve.py` 双栈启动器）+ 对应回归用例（+4 条）。

## 🔄 设置页"系统更新"卡片（在线检查 / 拉取 / 回滚，管理员专属）

- **新增在线自更新**（`utils/updater.py` + `routers/system.py`，public 仓库匿名 `git fetch`，无需配置密钥）：
  - `GET /api/check-update`：fetch 后比较本地 HEAD 与 `origin/main`，返回 `{behind, commits[], dirty[]}`——只读，不动工作区
  - `POST /api/apply-update`：① 工作区脏（未提交改动）→ 拒绝（防误伤本地改动）② 旧 HEAD 记入 `data/update_log.json` ③ `git merge --ff-only origin/main` ④ 本次 diff 触及 `requirements.txt` 才 `pip install` ⑤ 冒烟（`py_compile` 全量 + `import main`）失败 → 自动 `git reset` 回旧 HEAD、服务保持旧版 ⑥ 配置了 `restart_command` 才调度 detached 重启（sleep 2 后执行，HTTP 先返回），留空则提示"请手动重启"
  - `POST /api/rollback-update`：24h 窗口内一键 reset 回最近一次成功更新的旧 HEAD
  - `GET /api/system-info`：当前 git commit + 最新版本号（读 `release_note/`）+ 最近 3 条更新记录
- **鉴权**：`main.py` 把 4 端点纳入 `require_token` 保护列表（无 token → 401），端点内再校验 `user_manage`（非管理员 → 403）+ `update_enabled` 开关（关闭 → 403），三重闸门
- **前端**（`static/index.html` + `app.js`）：设置页新增"系统更新"卡片（仅管理员可见）——当前版本/commit + [检查更新] → 落后 commit 列表 + [立即更新]（确认弹窗；配了重启命令则注明"将自动重启"）+ [回滚] + 脏工作区告警 + **重启命令输入框（默认留空 = 不自动重启、不猜测系统/服务名）**；更新成功后轮询 `/api/settings` 等复活（30s），复活后提示硬刷新浏览器；更新按钮 10s 冷却防连点
- **配置键**（`utils/storage.py`，幂等补齐）：`update_enabled: true` / `update_branch: "main"` / `restart_command: ""`（空 = 手动重启，安全降级）；全量保存设置时随 `saveSettings` 回传，防被覆盖洗掉
- **立即重启**：卡片"重启命令"输入框旁新增 [立即重启] 按钮（`POST /api/restart-service`，管理员 + `update_enabled` 双闸门）——先保存输入框命令再按 config 值调度 detached 重启（sleep 2s，与更新/回滚同款机制，写 `update_log` 留痕 `manual-restart`）；未配置命令时返回 `need_cmd` 提示不猜命令；前端成功后轮询 `/api/settings` 等复活并提示硬刷新
- **安全边界**：分支固定 `origin/main`（无任意 URL/命令注入面）；重启命令只整条执行、不与请求参数拼接；`uploads/cache/data/config` 均在 git 跟踪外，`--ff-only` 只动代码文件，数据零影响；每次操作写 `update_log` 留痕（who/时间/from→to/结果）
- **运行修复**：`git fetch` 遇 `dubious ownership`（服务以 SYSTEM/其它用户身份运行、HOME 无安装者配的 safe.directory）时自动以**当前进程身份**写 global safe.directory 并重试一次（自愈，不依赖安装时配置归属）；修正 `UPDATE_LOG` 路径多取一级 `dirname` 误写到项目上级 `data/` 的缺陷（迁回项目内 `data/update_log.json`）

## 📦 一键安装 / 卸载脚本（install.py + serve.py）

- **`install.py`（跨平台，幂等可重跑）**：`python install.py [--service] [--ipv6] [-p 端口] [--uninstall]`
  - **环境准备（脚本只检测不代装，详见 README"环境准备"表）**：Python ≥ 3.10（必需）、ffmpeg（建议，缺则缩略图/DASH 不可用）、git（建议，缺则在线更新不可用）、uv（可选，加速 venv/依赖安装，缺则退回标准库 venv+pip）；各依赖附 Windows/Linux/macOS 安装命令
  - 前置**只检测不自动装**：Python ≥ 3.10（硬性）、ffmpeg / git（缺失仅警告 + 给各平台安装命令，不阻断基础功能）
  - 虚拟环境：**`.venv` 存在即复用**（有 uv 用 `uv pip` 补差，uv 建的 venv 无 pip 模块也能装）；没有则 **uv 优先创建**；无 uv 退回标准库 `venv + pip`（并提示装 uv 提速）；复用/新建后若 venv 仍缺 pip（uv venv + 当前终端无 uv 的组合），自动 `python -m ensurepip` 引导补上再装依赖
  - 建运行时目录（`uploads/cache{,thumbs,zips,dash,video}/data/config`）+ 生成启动器 `run.bat`（Win）/ `run.sh`（POSIX）
  - **自动配置 `git safe.directory`**（幂等）：安装时把项目根动态追加进 `git config --global safe.directory`（已含则跳过，不硬编码路径），防仓库属主与当前用户不一致（跨账号克隆 / 网络目录 / zip 解压部署）时在线更新的 `git fetch` 被 `dubious ownership` 拒绝
  - `--service` 使能即装、失败再提示（失败时收尾文案如实显示"安装失败"，不误报"已启用"）：Linux 生成 `xs-file-lib.service`（有 sudo 装系统服务并 enable --now，无 sudo 降级 user unit，再失败打印手动三步）；**Windows NSSM 优先**（`find_nssm()` 探测用户 PATH → 项目根 `nssm.exe`，命中即装真服务 `XsFileLib`：开机自启 + 崩溃守护，`AppDirectory`/日志重定向 `logs/`，幂等先 remove 后建；未装 NSSM 或安装失败回落 `service_run.bat` + 计划任务 `XsFileLibService`（管理员 ONSTART/SYSTEM，普通用户 ONLOGON））
  - **`restart_command` 默认跟随安装类型**：服务装成后按实际路径把重启命令原子写进 `config/config.json`（系统服务 `systemctl restart xs-file-lib` / user 服务 `systemctl --user …` / NSSM `nssm restart XsFileLib` / 计划任务 `schtasks /End && /Run` 组合）——设置页"系统更新"卡片自动回显，无需手填。覆盖策略：空值与安装生成的已知默认值 → 预填/覆盖；**用户自定义值一律保留**；`--uninstall` 移除服务后清空已知默认值（自定义保留）。未装服务时不写（保持空 = 手动重启语义不变）
  - **`--uninstall`（仅卸载服务，不删业务数据）**：Windows 删计划任务 `XsFileLibService` + 探测移除 NSSM 服务 `XsFileLib`（若装了）+ `service_run.bat`；Linux 移除 systemd user/系统 unit + 生成的 `xs-file-lib.service` 文件。全幂等（未安装即跳过，连跑不报错，失败只警告不中断）；完成后打印**剩余文件清单**（`.venv/`、`run.bat`/`run.sh`）并提示业务数据 `uploads/ data/ config/ cache/`（账号、共享链接、HMAC 密钥、缓存）未删除、需自行清理
- **`serve.py`（双栈启动器，`--ipv6` 时由 install.py 生成的启动命令使用）**：`python serve.py --host :: --port 8000` 在**同一端口**收 IPv4 + IPv6 连接——显式 `setsockopt(IPV6_V6ONLY=0)` 解决 Windows 默认 V6ONLY=1（`::` 不收 IPv4）与 Linux 行为不一致的问题（已实测同端口 IPv4/IPv6 均 200）；`--host 0.0.0.0` 时与 uvicorn CLI 等价
- 与"系统更新"卡片配套：服务化后 `restart_command` 填 `systemctl restart xs-file-lib`（Linux）或 `schtasks /Run /TN "XsFileLibService"`（Windows 计划任务）/ `nssm restart XsFileLib`（NSSM）
- 注意区分：`--ipv6` 控制**服务监听**（双栈）；设置页 `ipv6_base_url` 是**共享页媒体改道基址**，两者独立
